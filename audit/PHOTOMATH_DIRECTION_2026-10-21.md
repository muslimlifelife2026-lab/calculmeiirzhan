# Направление развития: решение задач по фото

Это план возможностей, а не заявление об их готовности.

Обновление 2026-10-22: первый этап реализован в 1.3.0 — системы 2×2, карточки шагов, галерея, сохранение полного уравнения и связанные графики. Ниже сохранено исходное сравнение; актуальные проверки и ограничения описаны в [отчёте 1.3.0](RELEASE_1_3_0_2026-10-22.md).

У Photomath основная цепочка — сканирование или ручной ввод → решение → объяснение шагов. Также заявлены разные методы решения и интерактивные графики. Источники: [официальный сайт](https://www.photomath.com/), [страница Google Play](https://play.google.com/store/apps/details?id=com.microblink.photomath&hl=ru).

| Возможность | Состояние AeroCalc на момент сравнения |
|---|---|
| Снимок печатного примера | Есть CameraX и локальное распознавание ML Kit |
| Проверка и исправление распознанного текста | Есть диалог подтверждения |
| Арифметика и объяснение операций | Есть калькулятор и решение по шагам |
| Линейные и квадратные уравнения с x | Есть отдельный раздел алгебры |
| Упрощение и производные полиномов | Есть; степень ограничена 12 |
| Интерактивные графики | Есть отдельный инструмент |
| Единый путь от фото уравнения к решению | Требует доработки: OCR сейчас отбрасывает правую часть после =, а сканер направляет текст в арифметический калькулятор |
| Выбор изображения из галереи | Пока нет в сканере |
| Двумерные дроби, системы, неравенства, произвольный почерк | Полноценная поддержка не реализована |
| Несколько методов для каждой задачи, анимированные объяснения | Не реализовано универсально |

Предлагаемый первый этап:

1. Камера и выбор изображения через системный выбор фотографий.
2. Редактируемый предпросмотр распознанного примера; сохранение обеих частей уравнения.
3. Автоматический выбор арифметики или решателя линейных/квадратных уравнений.
4. Экран ответа с точными значениями и понятными шагами, переход к связанному графику.
5. Проверки ошибочного OCR, неподдерживаемых задач, отмены обработки, больших изображений и сохранения черновика.

Первый этап должен честно указывать поддерживаемые форматы. Обычный OCR нельзя выдавать за надёжное распознавание рукописных математических конструкций.

Следующие этапы: системы линейных уравнений и неравенства; альтернативные методы; интерактивное объяснение «почему»; упражнения на закрепление.

У Photomath обработка изображений описана как облачная. Это не означает, что AeroCalc должен отправлять фотографии на сервер: существующие базовые вычисления и распознавание можно развивать локально. При выборе облачного распознавания понадобятся отдельные решения о сервисе, стоимости и обработке изображений. [Описание архитектуры Photomath](https://support.google.com/photomath/answer/14328660?hl=en).
